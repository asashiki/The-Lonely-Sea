# 过程与设计依据

## 关于“思考过程”

本文提供的是可公开、可复用、能解释结果的设计判断与取舍，不是模型私有的逐 token 内部推理。它足以说明为什么采用这条生成路径，也方便以后复刻或改进。

## 1. 先把问题拆成“地点”与“状态”

目标不是四张彼此无关的海景，而是 Galgame 中同一个地点在不同时间或情绪状态下的差分背景。因此流程没有分别从零生成四张图，而是：

1. 先生成一张能确立机位、海岸线和留白的灰雾母版。
2. 把母版作为后三张图的第一输入。
3. 让第二输入只提供晴天、暗夜或深红状态的色彩语言。
4. 在提示词中反复声明“只改光照、天空、氛围与色彩”。

这能显著减少海岸线漂移，让场景切换更像游戏背景差分。

## 2. 为什么选择这种画风

项目需要现代网页结构，但画面仍要有 Galgame 的作者感。纯写实海景或细节过量的现代概念图会产生三个问题：

- 容易显得像摄影素材或常见 AI 壁纸；
- 抢走未来 Live2D 角色和菜单的视觉焦点；
- 四种状态之间很难保持统一的“同一张背景差分”感。

所以提示词把媒介锁定为：

- 2000 年代末至 2010 年代初的日式视觉小说背景；
- 手绘 2D；
- 淡水彩罩染与少量墨线结构；
- 纸张颗粒、颜料晕染和不完全均匀的作者化痕迹；
- 简化形体、低对比、不过度刻画。

同时明确排除摄影、3D、油亮的现代 AI 概念图和超精细渲染。最终四张图的统一感，主要来自“手绘媒介不变 + 地点构图不变 + 仅状态变化”。

## 3. 为什么画面这么空

空并不是缺少设计，而是为网页层级主动让位：

- 左半边是未来 Live2D 角色的舞台；
- 右侧约三分之一是无面板纵向菜单的低对比区；
- 中央不放强焦点，避免人物、标题和菜单相互争抢；
- 不设置硬竖边，减少超宽屏 `cover` 裁切时出现明显接缝的风险；
- 地平线约在画面高度 44%，使天空、海面与沙滩都有足够层次。

背景保持简单，也符合许多 Galgame 标题界面“人物与 UI 是主角，场景负责气氛”的构图习惯。

## 4. 灰雾母版的建立

母版使用三张实际参考图，每张只承担一个职责：

- 第一张：灰蓝水彩、雾气和低对比画风；
- 第二张：超宽负空间和视觉重心分配；
- 第三张：寂静岸线与沙滩情绪。

提示词要求只借用调色、手绘质感和构图原则，并明确禁止复制人物、文字、Logo 或可识别设计。母版最终成为 `01-mist.png`。

## 5. 三张差分状态

三张状态图以同一灰雾母版为第一输入，并各自添加一张色彩参考：

- 晴天：提取淡青蓝天空、白云、蓝绿海水和柔和日照，同时保留孤独感，避免变成旅游海报。
- 暗夜：提取低饱和靛蓝、近黑海面和冷色浪尖，保留暗部层次以承载浅色 UI。
- 黑血红深夜：提取黑、脏深红和酒红的语言；红色被定义为异常光，而不是血液或具体暴力物。

原执行中三张差分任务并行提交，但它们互不依赖；关键不是并行本身，而是都依赖同一母版。

## 6. 负面约束为什么很长

参考图中含有少女、伞、文字、水印、岩石、杆状物或其他叙事对象。若只说“参考画风”，生成器仍可能把这些对象一起带入。因此每个提示词都按对应参考图逐项排除：

- 人物、剪影、伞、鸟；
- 文字、歌词、Logo、水印、UI、边框；
- 建筑、碎片、杆子等会改变场景叙事的对象；
- 摄影、3D、现代油亮概念图；
- 雪、雨和前景粒子。

这既降低复制风险，也保持背景可供网页分层使用。

## 7. 实际中间产物

本次没有“灰雾草稿 1 / 草稿 2 / 调色稿”之类被遗漏的生成中间图。唯一真正的中间件就是灰雾母版，而它本身也被选为第一张成品。资料包在 `03-intermediate-images/` 中另存了一份，专门强调它在后三张图中的工程角色。

## 8. 以后扩展时最应保留的内容

新增黄昏、暴雨、月夜或异常色状态时，应优先保留：

- 同一母版作为第一输入；
- “preserve exact camera position / coastline geometry / horizon height / wave placement”；
- 左侧角色舞台和右侧菜单负空间；
- 手绘水彩、纸张颗粒和简化细节；
- 只改天气、光色、天空与氛围；
- 针对第二参考图逐项写清不可复制对象。
