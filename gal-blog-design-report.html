01 / VERDICT

这次真正需要做的，不是“搬家”，而是重新分层。

旧站已经有成熟内容与功能；新仓库已经有足够多的视觉原型。缺的不是更多单页 Demo，而是生产内容模型、真实路由和清楚的复用边界。

A

保留 Astro

它天然适合内容驱动站点。正文静态生成，菜单、播放器、进度与画廊才做交互岛，不需要全站 SPA 或游戏引擎。

B

不整包换皮 Fuwari

复用 Markdown、RSS、搜索、目录与内容工具；放弃其 banner、侧栏、卡片栅格这套视觉外壳。

C

先打通一条真实链路

标题 → LOAD → 一篇真实文章 → CONTINUE → 简洁模式。成立以后再扩 EXTRA。

!
一个必须先修的旧站问题

Asashiki 本地工程的 astro.config.mjs 与 RSS fallback 仍指向 fuwari.vercel.app。迁移前先统一 site=https://asashiki.com，再检查 canonical、RSS、sitemap 与 OG 绝对地址。

02 / THE GALGAME TEST

像 Galgame，不等于“动漫背景 + 六个英文按钮”。

从视觉小说引擎的菜单、Save/Load、Gallery、Music Room、Replay 与 Persistent Data 语法反推，真正的感觉来自舞台、反馈与状态连续性。

持久舞台

背景、角色、标题和菜单组成同一场景；二级菜单沿用场景，而不是跳进普通卡片站。

菜单语法

START、CONTINUE、LOAD、EXTRA、OPTION 都有清晰且真实的网页职责。

状态记忆

阅读进度、收藏、解锁、主题与音量会跨访问保留，按钮状态随之变化。

收藏与回想

CG、项目、年度回想与音乐室使用缩略图、分组、进度和详情层来展示。

阅读克制

离开标题画面后，正文回归正常滚动、可复制、可链接、可搜索的文档。

≠
核心边界：内容不能被“游戏流程”锁死

解锁可以改变徽章、排序与演出，但文章、项目和 CG 都应拥有稳定 URL；首次对白必须可跳过，之后默认不再强制播放。

03 / INFORMATION ARCHITECTURE

把游戏菜单翻译成博客职责，而不是只翻译名字。

主菜单保持六项，复杂内容全部进入二级界面。外观可以游戏化，URL 仍然使用普通网页语义并尽量兼容旧站。

01

STARTはじめから / 初次进入

3–5 句可跳过序章 + 路线导览

不是文章首页。给第一次来的访客解释“这里是什么”，然后让他选择文章、项目、追番或关于。

02

CONTINUE続きから / 继续阅读

恢复最后文章、标题锚点与滚动比例

没有记录时呈禁用态并说明原因；不要偷偷跳到“最新文章”。

03

LOAD記事の記録 / 文章存档

归档 + 标签 + 分类 + 搜索 + 收藏

文章以存档槽展示。类别可称 Route，年份可称 Chapter，但界面里仍显示原始标签与时间。

04

EXTRAおまけ / 收藏室

CG、Works、Bangumi、Recollection、Music、Character

这里是个人网站的世界观中心，也是项目、追番、时间线与热力图的自然容器。

05

OPTION環境設定 / 页面设置

字号、动效、BGM、SE、主题、场景、数据

设置不只是装饰；始终提供关闭音乐、减少动效、恢复默认与清理本地记录。

06

EXIT終了する / 离开演出

切换到 Plain Mode，而不是调用 window.close

普通导航、无舞台、无 BGM、弱动效；也可提供“返回来源页”。

04 / PAGE BLUEPRINTS

每一页怎么展示：氛围浓度应当逐层下降。

标题最像游戏，Extra 次之，文章最像网页。这样既有“进入作品”的仪式，也不会让每次阅读都付出交互成本。

TITLE / HIGH IMMERSION

标题页：用现有 Kimi / Alice 方向做最终皮肤

桌面 16:9 构图，左侧标题和六项菜单，右侧 Alice 与房间；首次点击 ENTER 同时解锁音频权限。第二次访问直接到标题，不再强播启动 Logo。

  • 鼠标、键盘、触屏都可选菜单
  • 角色点击只做短台词，不挡导航
  • 移动端改为竖向裁切，不能强迫横屏
START / MEDIUM

序章：三步内结束

Alice 用 3–5 句说明网站，然后出现四个选择：文章、项目、追番、关于。提供 SKIP，读过后不再自动出现。

LOAD / MEDIUM

文章存档：像存档槽，但有博客信息

每格显示封面、标题、日期、分类、标签、阅读时长与进度。顶部保留 ALL / ROUTE / TAG / YEAR / SEARCH。

ARTICLE / LOW IMMERSION

文章页：正文不是对白框

用纸张/书页式大面板承载普通 Markdown。场景只留在页首封面或淡背景；正文宽度、行距、目录、图片、代码块、脚注与复制行为全部遵循正常博客。

  • 顶部：标题、摘要、日期、类别、标签、封面
  • 侧边/底部：目录、上一篇/下一篇、回到 LOAD
  • 保存当前位置；特殊年报可选择“视觉演出版”
EXTRA / COLLECTION HUB

项目页和 CG 页共享画廊语法，但必须是两个入口

你想把 GitHub 项目做成 CG 缩略图，这个比喻很合适；但不要牺牲真正的 CG。建议 EXTRA 首层并列 CG GALLERY 与 PROJECT ARCHIVE：前者打开插画灯箱，后者先打开项目详情层，再选择 Live / Repository。项目卡可显示 Live、Repo、Planned 状态和技术标签。

BANGUMI / RECORDS

追番：收藏室 + 活跃记录

“在看”优先，热力图作为头部仪表；动画/游戏与状态筛选保持。条目点击打开详情抽屉，再去 Bangumi。

RECOLLECTION / ENDINGS

回想：收纳年度报告与精选长文

现有动画/游戏年度报告和 AI visual JSON 很适合成为特殊演出版；正文仍是唯一内容源，演出版是 presentation。

TIMELINE / MEMORY LOG

时间线：把生活轨迹做成 Route Map

时间胶囊按年/月和来源筛选；状态页独立为 SYSTEM MONITOR，实时失败时显示最后更新时间与静态快照。

CHARACTER / STAFF

关于、友链、Credits

About 可做角色档案；Friends 可做 Staff / Neighbours；新增 Colophon/Credits 记录技术栈、图片来源、音乐授权与版本变更。

QUICK LOAD

全站搜索不藏在菜单深处

保留快捷键和显眼按钮，命名为 QUICK LOAD；Pagefind 结果必须能直接到真实文章锚点。

404 / LOST SAVE

404 可以玩，但要给出口

“存档损坏 / 找不到章节”的演出之后，立即给 TITLE、LOAD、SEARCH 三个可用按钮。

05 / MIGRATION INVENTORY

旧 Asashiki 与现有原型，各自只拿它最强的一部分。

当前 gal-blog 不是生产工程：只有单文件原型与素材。最优路线是把旧站当内容/功能供体，把四个新原型拆成信息架构、视觉皮肤、阅读验证和状态交互。

06 / TECHNICAL ARCHITECTURE

推荐栈：Astro 7.1 + TypeScript + Svelte 5 islands。

Astro 7 已在 2026 年 6 月稳定发布，当前绿地工程应锁定 7.1.x 与 Node.js 22.12+。新仓库没有应用骨架，适合直接使用新工程；旧站保持在线，只做内容与功能的逐块迁移。

实现上的四个决定

  • 真实 <a> 和文件路由是底座；JS 失败仍可读文章。
  • 新 Gal UI 用 CSS variables + 语义 class；Tailwind 只为迁移组件暂留。
  • 优先使用浏览器/Astro View Transitions；不再叠一层 Swup。
  • 持续 BGM 只做一个持久播放器 island；所有脚本监听 Astro 生命周期并幂等。

API
第三方数据不能成为页面或构建的单点故障

当前 GitHub 热力图依赖 jogruber API，Bangumi 热力图依赖 bgm.ry.mk，收藏走官方 api.bgm.tv。建议统一成 adapters：设置超时、缓存、最后成功 JSON 与独立错误状态；项目正文和基础页面永远不被它们卡住。

08 / GUARDRAILS

最容易把这个项目做坏的九件事。

这些不是“以后优化”，而是设计边界。尤其是音频、素材授权、真实 URL 与第三方 API。

R01

整站固定 16:9

标题舞台可 16:9，正文必须正常纵向滚动；移动端不能要求横屏。

R02

每次强制序章

Boot/Start 首次播放、可跳过、可在 Option 重播；回访直接到菜单。

R03

用“解锁”藏公开内容

解锁只影响演出和标记，不能阻止深链接、搜索引擎或 RSS 访问。

R04

自动播放 BGM

必须经过用户点击；静音、音量与停止按钮始终可见，设置持久化。

R05

把 Projects 当掉 CG

共享画廊语法即可；PROJECT ARCHIVE 与 CG GALLERY 保持并列。

R06

远端 API 卡住构建

超时、缓存、静态快照、最后更新时间和独立空态都要存在。

R07

继续堆单文件原型

原型已经够用；下一步必须进入 content collection、组件和真实路由。

R08

把参考图直接上线

当前参考素材没有授权台账。未确认许可前只做研究，不进入生产 assets。

R09

一次提交 84MB 未跟踪素材

先去重、分类、压缩与登记来源，再只纳入最终会使用的文件。

FINAL RECOMMENDATION

用 Asashiki 作为内容数据库，用 Astro 作为博客引擎，用 Galgame 的舞台、菜单、存档、回想与 EXTRA 作为信息架构语言。

一句更具体的话：先以 Kimi 原型的视觉、alice-title 的页面地图、retro vertical slice 的阅读层、asashiki-galgame 的状态交互，拼出一条真实的“TITLE → LOAD → ARTICLE → CONTINUE”链路；验证后再迁移 PROJECTS、CG 与 BANGUMI。
