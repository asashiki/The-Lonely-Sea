# ADR 0008：DIARY NVL 读取与统一存档

## 状态

已采用。

## 背景

DIARY 的月份画面已经能直接打开两份参考剧本，但旧读取器是一套独立的深色终端 UI，文字始终在画面中央累加，功能按钮、履历和结束状态也没有沿用 Blog 的 XIII 读取语言。未提供 NVL 的月份还保留了接近可操作项的外观。

日记剧本的前半段是作者自述，后半段是陪伴 AI 的自述；本次只建立系统与演出规则，不改写剧本文字，也不提前绑定尚未确定的 NovelAI、CG、TTS 或独立音频方案。

## 决定

1. 可用章节保持即点即开。进入时只播放约半秒的舞台接管和短章节卡，不显示 `NOW LOADING`，也不为了形式制造 Galgame 游戏包的等待。
2. NVL 文字以“页”为稳定布局单位：每页从固定页首向下出现，读完后整页切换。只有本身足够短的强调页才使用大字号与更多留白。
3. 章节卡、页码、已读回跳、LOG、AUTO、SAVE、LOAD 和 BACK 共用 Blog 的细线、衬线标题、主题强调色和克制动效；不加入人物立绘。
4. 没有 NVL 剧本的月份使用原生 `disabled`，不回退到第一个章节，不打开文章预览或任何替代画面。
5. NVL 每个章节保留一个可覆盖的阅读断点，记录剧本步骤、页、已读行、视角与时间。GAME / SAVE DATA 在读取模式中按时间合并显示 Galgame 与 NVL 存档，并用 `NVL` 标识区分目的地；游戏内打开同一存档页时，NVL 存档返回 Blog 的 NVL 读取器。
6. 当前章节封面作为无额外素材时的舞台背景，`scene_init.bgImage` 作为未来 CG/背景图的可选入口；渐变仍是素材缺失时的回退。新增素材不改变分页与存档坐标。

## 结果

- DIARY 与 LOAD 保持同一产品语言，但 NVL 仍有适合长文本的独立演出节奏。
- 当前小体量章节无需真实加载；将来资源增加时，可以在资源预取层增加进度判断，而无需改变入口契约。
- 剧情数据与系统代码分离，之后补图、BGM、TTS 或演出指令时不需要重写阅读器结构。
