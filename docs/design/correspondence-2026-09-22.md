# OPTION 与通讯页调整

分支：`codex/latest-nvl-20260910`

## 页面

- OPTION 保留顶部四个入口和原设置逻辑，把已交付原型的内容区接入正式页面；原型留在 `prototypes/option-sea-preview.html`，图片引用仓库现有文件。
- 通讯页复用已保存的海面主题，包含浅色薄雾/白昼及深色夜海/绯红。移除原先为不存在的立绘保留的空列；友链与填写区并列，手机上纵排。
- 文章末尾留言恢复可见标签和多行编辑空间；游戏内来信保留角色旁的位置，重新统一输入控件和正文间距。

## 行为

- 未提交文字存于独立的本机草稿键，按文章/游戏上下文区分；关闭后再开仍可恢复。最多保存 30 份，存储失败会提示。
- 正在提交时防重复点击。失败不清空输入，当前实例重试复用本机记录；收到响应后也不会清空期间继续输入的新内容。
- 没有 `PUBLIC_LIGHTHOUSE_MESSAGE_ENDPOINT` 时明确显示“保存到本机/保存申请草稿”。新增 GitHub 公开提交入口，只打开预填的 issue 编辑页，访客确认后才提交。
- 本机留言列表不是全站公共评论流。此改动没有新增服务端评论数据库、审核后台或公共评论同步。
- 友链表单增加选填介绍，沿用既有接收字段；禁止 javascript 等非 HTTP(S) 地址。
- 通讯页的 Escape 不再打断输入；从浏览器往返缓存恢复时保留控制器。
- 2026-08 三种语言的日记原稿不再进入运行时导入图，灰显入口仍保留。GitHub 中原稿与历史未删除；这是网站发布范围的修正，并非仓库历史清理。

## 验证

- `pnpm build` 完成类型检查、20 个页面生成与 Pages 打包。0 errors / 0 warnings；仍有原有音频代码的两处 unused 提示和大 chunk 提示。
- `pnpm test:communication`：使用构建后的 HTML 与实际控制器，验证跨上下文草稿恢复、本机保存、防重复提交、失败重试、提交中继续编辑、地址校验、存储受限，以及 GitHub 仅打开编辑器、留言按纯文本渲染。网络请求在测试中模拟，不向真实收件服务发送消息。
- 构建产物中的 NVL JSON 在所有语言下仅含 April / June；没有 August 原稿 JSON。
- 本轮未完成真实浏览器的视觉截图验收，不将 DOM 交互测试等同于视觉验收。

测试命令：先在未配置收件 endpoint 的环境执行 `pnpm build`，再执行 `pnpm test:communication`。jsdom 仅作为开发测试依赖，不进入网站运行时。
