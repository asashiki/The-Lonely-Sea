# 从标题画面到文章

这轮的设计对象是完整的阅读过程。之前 LOAD 只有一组封面槽，文章打开后又回到窄幅长文；两边缺少联系，也没有告诉初访者这个站点有哪些可以直接阅读的内容。

## 已实现

- **首页**：初访时展示最新文章的封面、标题、日期与预计阅读时长，附文章目录入口。有继续记录时，仍展示 CONTINUE。主菜单新增随指令变化的简短说明，不改变原有指令的位置和英文名称。
- **LOAD / ARTICLES**：左侧是一幅随选择变化的文章画面，配摘要与读取指令；右侧是六行编号索引。只按真实文章分页，不再补满 24 个空槽。文章分类、GAME、DIARY 及公共导航仍使用原来的体系。
- **文章开场**：大幅插画与题署分开构图，进入正文前可以先看标题、摘要、分类和大致阅读时长。封面仍可以放大查看，现在也支持键盘进入。
- **正文**：桌面目录显示完整章节名；窄屏用可展开目录。正文回到固定阅读宽度，字号和行距继续受 BLOG 设置控制。专注模式收起天气、音乐控件和旁侧界面，保留明确退出按钮。
- **篇章衔接**：文末相邻文章增加封面；读取系统内打开文章时，在支持的浏览器中衔接所选封面与篇章插图。减少动态效果开启时直接切换。

没有新增剧情台词，没有修改文章正文和 DIARY 内容，也没有改变停用归档的状态。

## 取舍

首页的背景和菜单已经足够鲜明，这轮不再往上堆装饰。阅读部分使用站点自己的四套场景色、已有画面和字体，让选择内容、打开篇章、安静阅读有各自的节奏。目录中的编号对应章节次序；选中状态依靠字色和字重，不追加边条、菱形或圆点。

阅读时长按正文中的中日文字数与其他语言单词数估算，始终标为“约”。它不是实际计时，也不包含停下来看图的时间。

封面衔接使用同文档 View Transitions，保留即时切换作为回退。首页加载文章仍走已有 iframe 宿主，未将它宣称为跨文档封面转场。

- [MDN：Document.startViewTransition](https://developer.mozilla.org/en-US/docs/Web/API/Document/startViewTransition)
- [Chrome：跨文档 View Transitions 的条件与边界](https://developer.chrome.com/docs/web-platform/view-transitions/cross-document)

## 预览与验证

打开 `prototypes/reading-journey-preview.html` 可以切换首页、LOAD 和阅读页，也可以切换雾、昼、夜、绯四种场景。它由构建后的真实页面、样式及交互模块生成，包含七篇公开文章的文字和封面；正文配图及在线服务留在正式站。复现：`pnpm build` 后执行 `node scripts/build-reading-preview.mjs`。

生产构建通过。定向检查覆盖文章选择与空分类、七组完整页面与阅读片段的一致性、专注模式退出及原生转场回退。浏览器环境未能连接本地预览，尚未完成桌面、手机的实际截图验收；静态预览不应被当作已通过像素验收的证明。

下一轮值得继续做的是友链与留言的完整相遇过程：从站外入口到作者简介、留言上下文和返回位置，而不只是再换一层容器。这轮先把首页到文章这条路落实，避免同时改动所有功能。
